# 불확실성 표시 규칙

beopsuny의 `[VERIFIED]/[UNVERIFIED]/[STALE]` 방식을 참고하되, LawLint는 사내변호사가 아니라 코딩 중인 개발자를 대상으로 하므로 라벨을 3개로 줄인 경량 버전을 쓴다([LawLint_계획_최종.md](../LawLint_계획_최종.md) Day 9 메모).

## 라벨 3개

| 라벨 | 뜻 | 조건 |
|---|---|---|
| `[VERIFIED]` | 이번에 공식 원문을 직접 대조했다 | law.go.kr 원문, korean-law-mcp 원문 필드, 또는 beopsuny의 `[VERIFIED]` 응답을 실제로 열어본 경우만. **조문 번호가 맞다는 것만으로 부족하다 — 해당 조문에 최근 개정(신설된 항·호 등)이 없는지까지 원문에서 확인해야 한다.** 할루시네이션 테스트에서 조문 번호(3%)는 맞았지만 2026-03-10 신설된 상위 항(10%)을 놓친 사례가 실제로 나왔다([examples/hallucination-test.md](../examples/hallucination-test.md)) |
| `[UNVERIFIED]` | 트리거는 걸렸지만 원문 대조를 못했다 (기본값) | 검색 스니펫·블로그·과거 캐시만 본 경우. 트리거 최초 감지 시 항상 이 상태에서 시작 |
| `[INSUFFICIENT]` | 조회 자체가 실패했다 | law.go.kr 접속 실패, korean-law-mcp/법망 API 무응답, 관련 조문을 못 찾음 |

beopsuny 고유 라벨(`[CONTRADICTED]`, `[EDITORIAL]`)은 가져오지 않는다 — LawLint는 상충 근거를 정밀 대조하는 도구가 아니라, 개발자에게 "확인해봐야 할 지점"을 짚어주는 1차 감지 도구이기 때문이다. 상충이 발견되면 `[UNVERIFIED]`로 낮추고 이유를 한 줄 남긴다.

## 표시 위치

각 리뷰 항목마다 라벨 + 확인 경로(provenance)를 붙인다.

```
[VERIFIED] 개인정보보호법 제24조의2 — law.go.kr 원문 확인 (2026-09-17)
[UNVERIFIED] 위치정보법 제9조 — 법망 API 검색 결과만 확인, 원문 미대조
[INSUFFICIENT] 여신전문금융업법 카드정보 저장 금지 — 정확한 조문 특정 실패
```

## 조회 실패는 "문제없음"이 아니다

korean-law-mcp/법망 API가 응답하지 않거나 관련 조문을 못 찾았다고 해서 "이 트리거는 걸리지만 법적 문제는 없다"고 결론 내리지 않는다. `[INSUFFICIENT]`로 표시하고 개발자에게 직접 확인을 권한다.

## 최신성

법 개정으로 시행 예정이지만 아직 시행 전인 조문은 "현재 적용 규칙"과 "시행 예정 규칙"을 분리해서 보여준다 (`rules/triggers.md` 8번 AI 특례 사례 참고 — 2026-09-08 공포, 2027-03-09 시행).
