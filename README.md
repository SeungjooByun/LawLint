# LawLint

> LawLint는 "물어보면 답하는 법률 비서"가 아니다. 개발자가 질문할 생각조차 못 한 순간에 코드를 먼저 보고 끼어드는 사전 감지 도구다.

법순이(beopsuny)가 물어보면 답해주는 사내 변호사라면, LawLint는 기능을 코드로 짜는 그 순간 어깨 너머로 지켜보고 있는 검토자에 가깝다. 회원가입 폼에 나이 확인이 빠졌거나, 개인정보처리방침 없이 개인정보를 수집하고 있거나 — 개발자가 굳이 "이거 괜찮나요?"라고 묻지 않아도 먼저 짚어준다.

> ⚠️ **법률 자문이 아니다.** 무료·비영리 오픈소스로 제공되고, 정확성을 보장하지도 않는다. 쓰기 전에 [DISCLAIMER.md](DISCLAIMER.md)를 읽어볼 것.

## 뭘 다루나

원래는 한국 AI 관련 법률만 다룰 생각이었는데, 실제로 개발자들이 부딪히는 건 AI 기능보다 개인정보·결제·저작권·세무 쪽이 훨씬 많았다. 그래서 지금은 **앱·웹 서비스를 만들면서 한국에서 마주칠 수 있는 법적 리스크 전반**을 다룬다 — 개인정보 수집부터 인앱결제, 사업자등록 시점, 외주 계약, 위치정보 신고까지.

법률 지식을 외워서 답하지 않는다. 코드에서 트리거가 걸리면 그 자리에서 law.go.kr 원문을 직접 대조하고, 확인이 안 된 내용은 `[UNVERIFIED]`라고 솔직하게 표시한다.

## 구조

- `rules/` — 트리거 목록, 법률 판단 원칙, 불확실성 표시 규칙
- `workflows/` — 트리거가 걸렸을 때 실제로 조문을 검증하는 절차
- `templates/` — 리뷰 결과를 출력하는 포맷
- `examples/` — 실제로 트리거를 재현해본 사례들
- `tests/` — 트리거가 제대로 걸리는지 확인하는 테스트 케이스

## 지금 상태

v0.1이고, `SKILL.md`는 실제로 동작한다. 트리거 47개(`rules/triggers.md`)를 갖고 있고, law.go.kr 실시간 검증([workflows/trigger-to-verification.md](workflows/trigger-to-verification.md))을 붙였고, 재현율·할루시네이션·애매한 질문·엔드투엔드 드라이런까지 여러 방식으로 테스트해봤다(`examples/` 참고). 다만 47개 중 일부는 아직 `[UNVERIFIED]` 상태로 남아 있고, 실제로 트리거가 걸리는 순간 다시 검증하는 구조이지 목록에 적힌 조문을 그대로 믿는 구조는 아니다.

배경과 원래 4주 계획이 궁금하면 [LawLint_계획_최종.md](LawLint_계획_최종.md)를 보면 된다.
