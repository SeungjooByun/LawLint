# LawLint

> LawLint는 질문에 답하는 도구라기보다는, 물어보지 않아도 에이전트가 코드를 작성하는 동안 발생할 수 있는 법적 문제를 찾아서 알려준다.

현재 존재하는 beopsuny는 법률에 관한 질문을 해야 답을 받을 수 있는 구조이다. 하지만, LawLint는 사용자가 질문하지 않아도 코드를 계속 확인해서 회원가입 폼에 나이 확인이 빠졌거나 개인정보처리방침 없이 개인정보를 수집하고 있으면 먼저 문제가 있다고 알려주는 방식이다..

> ⚠️ **이 프로젝트에 공개된 모든 파일들과 스킬을 통해 생성된 답변은 법률 자문이 아니다.** 무료, 비영리 오픈소스로 제공되고, 정확성을 보장하지도 않는다. 쓰기 전에 [DISCLAIMER.md](DISCLAIMER.md)를 읽어볼 것을 추천한다.

## 무엇을 다루나

클로드 코드로 웹과 앱을 디자인하다 보면, 클로드 코드가 개인정보·결제·저작권·세무에 관련된 법을 고려하지 않아 뒤늦게 갈아엎은 적이 있을 것이다. 그래서 이 스킬은 **앱·웹 서비스를 만들면서 한국에서 마주칠 수 있는 법적 리스크 전반(개인정보 수집부터 인앱결제, 사업자등록 시점, 외주 계약, 위치정보 신고 등)**을 다룬다.

법률 지식을 외워서 답하는 것이 아니라, 코드에서 트리거가 걸리면 그 자리에서 law.go.kr 원문을 직접 대조하고, 확인이 안 된 내용은 `[UNVERIFIED]`라고 솔직하게 표시하도록 해 할루시네이션을 최소화하였다.

## 구조

- `rules/` — 트리거 목록, 법률 판단 원칙, 불확실성 표시 규칙
- `workflows/` — 트리거가 걸렸을 때 실제로 조문을 검증하는 절차
- `templates/` — 리뷰 결과를 출력하는 포맷
- `examples/` — 실제로 트리거를 재현해본 사례들
- `tests/` — 트리거가 제대로 걸리는지 확인하는 테스트 케이스

## 지금 상태

v0.1이고, `SKILL.md`는 실제로 동작한다. 트리거 47개(`rules/triggers.md`)를 갖고 있고, law.go.kr 실시간 검증([workflows/trigger-to-verification.md](workflows/trigger-to-verification.md))을 붙였고, 재현율·할루시네이션·애매한 질문·엔드투엔드 드라이런까지 여러 방식으로 테스트해봤다(`examples/` 참고). 다만 47개 중 일부는 아직 `[UNVERIFIED]` 상태로 남아 있고, 실제로 트리거가 걸리는 순간 다시 검증하는 구조이지 목록에 적힌 조문을 그대로 믿는 구조는 아니다.

배경과 원래 4주 계획이 궁금하면 [LawLint_계획_최종.md](LawLint_계획_최종.md)를 보면 된다.
