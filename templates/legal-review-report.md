# 리뷰 출력 포맷 (v0.1)

트리거가 걸렸을 때 개발자에게 보여줄 최소 포맷. 장황한 법률 자문서가 아니라 코드 리뷰 코멘트에 가깝게 짧게 쓴다.

```
🔍 LawLint: [트리거 번호·이름]

확인 대상: {파일:라인 또는 방금 작성한 함수/폼 이름 — 존재형 트리거는 구체적 위치, 부재형 트리거(1·16·35·36·37번 등)는 "무엇이 있는데 무엇이 없는지"를 한 줄로: 예 "회원가입 폼(UserDto)은 있는데 개인정보처리방침 없음"}
관련 가능성: {관련 법령명 + 조문(있으면)}
상태: [VERIFIED] / [UNVERIFIED] / [INSUFFICIENT]
확인 경로: {law.go.kr 원문 확인 / korean-law-mcp / 법망 API / 조회 실패}

확인이 필요한 것: {한 줄 — 예: "법정대리인 동의 분기 로직이 있는지"}
참고 링크: {law.go.kr 링크, 있으면}

⚠️ 이건 법률 자문이 아니라 확인 지점 안내입니다. 실제 처리는 직접 확인하거나 전문가 자문을 받으세요.
```

## 규칙

- 트리거 하나당 이 블록 하나. 여러 개 걸리면 개수만큼 반복하되, 우선순위 높은 것(개인정보처리방침 미게시처럼 전면적인 것)을 먼저.
- `[INSUFFICIENT]`인 경우 "확인이 필요한 것" 대신 "왜 확인에 실패했는지"와 "어디서 직접 확인하면 되는지"를 적는다.
- 같은 세션에서 이미 안내한 트리거를 코드가 안 바뀌었는데 반복해서 또 안내하지 않는다.
- 개발자가 "괜찮다고 확인했다"고 말하면 그 트리거는 그 세션 동안 다시 꺼내지 않는다 (매번 같은 경고를 반복해서 신뢰를 깎지 않는다).
