## 발견 1 — 트리거 1의 코드 패턴이 너무 좁다

트리거 1은 "생년월일 필드 수집"을 코드 패턴으로 잡는데, 이 프로젝트는 생년월일 대신 **자기신고형 boolean(`ageOver14`)**으로 미성년자 문제를 우회했다. 이건 실제로 흔한 대안 설계(생년월일 필드 자체를 안 만들면 법정대리인 동의 로직도 필요 없다고 판단하는 방식)라, 트리거 코드 패턴에 "나이 확인 boolean/체크박스"도 포함해야 한다 — 이런 방식이 실제로 법적으로 충분한지(자기신고만으로 만 14세 미만 필터링이 되는지)는 별도로 `[UNVERIFIED]`.

## 발견 2 — 트리거 38이 실제로 가장 "제대로 작동한" 사례

이 개발자가 겪은 과정(기능 출시 전 GitHub 이슈로 스스로 의심 → 제품 재설계 → 방통위 문의)이 LawLint가 지향하는 흐름과 정확히 일치한다. 다만 재설계 후에도 "사용자가 검색해서 고른 장소 좌표"가 여전히 위치정보법상 "개인위치정보"에 해당하는지는 이 개발자도 판단을 못 내리고 있다 — 트리거 38을 `[VERIFIED]`로 걸어놨지만, **"GPS 자동수집"과 "사용자가 입력한 장소"를 구분해서 판단해야 한다**는 세부 기준이 triggers.md에 없다. 추가 조사 필요 항목으로 남긴다.
