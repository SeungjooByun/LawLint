# 트리거 재현율 테스트 — 실제 저장소 4건 (rag-chatbot)

`github.com/changs0124/rag-chatbot` — OpenAI API(GPT-4o) + Vector Store 기반 RAG 챗봇(Spring Boot + React).

## 결과

| 트리거 | 결과 |
|---|---|
| 1 (나이 확인) | **또 부재형.** `User` 레코드가 `id, email, passwordHash, name, theme, role, createdAt, updatedAt`뿐. **4개 저장소 중 4개 전부 나이 확인 미흡/부재** — 표본이 늘수록 이게 예외가 아니라 사실상 기본값이라는 확신이 커짐 |
| 2 (AI API 연동) | **정확히 매치.** OpenAI 연동 테스트 파일이 15개 넘게 있고 실제 API 사용(`OpenAiRealUsageTest`, `OpenAiRealStreamingSpikeTest` 등)까지 존재 |
| 8 (챗봇 대화 재사용) | **트리거 정의를 다듬어야 할 사례.** 이 프로젝트는 RAG 구조라 관리자가 업로드한 문서(`AdminDocumentUpload...`)를 지식베이스로 쓰지, **사용자 대화 내용을 모델 학습에 재사용하지 않는다.** 기존 트리거 8은 "챗봇 대화 로그를 학습에 재사용"만 언급하는데, RAG의 "관리자 문서 기반 검색"은 이 문제와 무관 — 같은 "AI 챗봇"이라도 성격이 다르다는 걸 구분해야 함 |
| 35 (개인정보처리방침) | 매치 없음 — 이번에도 없음. RunningGu를 빼면 4개 중 3개가 처리방침 자체가 없었음 |
| 41 (보안조치) | **긍정적 신호**: `ConversationCrossAccessTest`라는 테스트가 존재 — 다른 사용자의 대화 기록에 접근할 수 없는지 직접 검증하고 있음. 41번이 우려하는 "접근통제 미비"를 이 프로젝트는 테스트 코드 수준에서 이미 방어하고 있는 사례 |

## 4개 저장소 누적 결과

| 트리거 | RunningGu | board | ecommerce | rag-chatbot |
|---|---|---|---|---|
| 1 (나이 확인) | 부분(자기신고) | 없음 | 없음 | 없음 |
| 35 (처리방침) | 있음 | 없음 | 없음(정당) | 없음 |
| 41 (보호조치) | — | — | — | 테스트로 검증 중(긍정) |

**결론**: 1번 트리거는 4전 4패로 실무에서 거의 항상 걸릴 만큼 흔한 문제로 확인됐다 — LawLint의 "부재형 감지" 능력이 실제로 가장 자주 쓰일 기능이 될 가능성이 높다. 반대로 8번(AI 학습 재사용)은 "AI API를 쓴다"는 것만으로 걸어버리면 이번 rag-chatbot 같은 정상적인 RAG 구현에 오탐할 위험이 있다 — "사용자 대화를 학습에 쓰는지" 여부를 구체적으로 구분해야 한다.
