# 회귀 테스트 스위트

LawLint는 프롬프트 기반 스킬이라 유닛테스트를 실행할 수 없다. 대신 "이 시나리오를 던지면 이 트리거가 나와야 한다"는 케이스를 모아두고, `SKILL.md`나 `rules/triggers.md`를 고칠 때마다 이 표를 다시 훑어 회귀가 없는지 확인한다.

## 사용법

1. Claude Code에 LawLint를 설치한 상태에서 아래 "시나리오"를 그대로(또는 유사하게) 요청한다.
2. 응답에 "기대 트리거" 번호가 걸리는지, `rules/uncertainty.md` 라벨이 붙는지 확인한다.
3. 아직 실 세션에 설치해서 돌려본 적은 없음 — 지금까지는 SKILL.md/triggers.md 내용을 직접 대조하는 데스크 시뮬레이션 방식으로 검증했다("질문 기반 시나리오 12건" 참고). 실제 설치 후 재현 결과가 다르면 이 표를 갱신할 것.

### 할루시네이션 테스트 (2026-09-17)

[hallucination-test.md](../examples/hallucination-test.md) — 블라인드 추측 4건 vs law.go.kr 실검증. 사전 조사 영향받은 2건은 정답, 순수 블라인드 2건 중 1건은 최근 개정(10% 가중 조항) 누락, 1건은 금액 자체가 틀림(3천만원→실제 2천만원). → 원칙 1(기억으로 답하지 않기), `[VERIFIED]` 조건에 "최근 개정 확인" 추가로 반영됨.

### 스킬 있음/없음 비교 — 토큰·품질 실측 3건 (2026-09-17)

[token-comparison-test.md](../examples/token-comparison-test.md) — 처음으로 별도 서브에이전트를 띄워 "LawLint 없이" vs "LawLint 절차대로"를 진짜로 비교함(그 전까지는 전부 데스크 시뮬레이션이었음). 트리거 25(인앱결제)·6+39(AI 채용 필터링)·27(비대면진료) 3개 시나리오. 결과: 스킬을 쓰면 토큰을 34~37% **더** 쓴다 — 이전에 "grep 방식이 86% 절감"이라고 측정한 건 트리거 파일 하나를 읽는 비용만 비교한 거지 스킬 전체 비용이 아니었다는 게 이번에 드러남. 대신 베이스라인이 완전히 놓치는 영역(한국법 미언급, 형사처벌 소지 무시)에서는 그 추가 비용만큼 실질적인 정확도 이득이 있었음.
